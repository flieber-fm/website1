## 3. How the site is built

- Static site generated by Python. Copy lives in `scripts/site_content.py` (plus `integ_content.py`, `work_content.py`); `scripts/build-content.py` writes the pages, `llms.txt`, `llms-full.txt`, `capabilities.json` and syncs parts of the homepage; `scripts/build-hubspot.py` writes HubSpot templates into `hubspot/build/`; `scripts/build-home-variants.py` writes `/home-variants/`.
- Hand-written pages: `index.html` (homepage prototype) and `pricing/index.html`.
- Rebuild: `python3 scripts/build-content.py && python3 scripts/build-hubspot.py && python3 scripts/build-home-variants.py`
- Cache busting: bump `site.css?v=N` across .html and .py files (around v68 now).
- `esc()` in build-content turns straight quotes into curly ones (opening ‘ after a space or bracket).
- Card rows use CSS subgrid so titles, bodies and heights align (the brief's layout rules). V16's CSS is page-scoped (`.pv-*`) inside its generator; move what the new pages reuse into `assets/css/site.css`.
- Railway does not auto-deploy reliably: after each push, call `connect-service-source` (repo flieber-fm/website1, branch `claude/website-positioning`) on service `website-positioning`, wait about 90 seconds, then `list-deployments`. railway.app is blocked from the container, so verify by deployment status and by local screenshots (Playwright, local `python3 -m http.server`).
- Check every page at 1360 px and 390 px: no horizontal scroll, no script errors, card rows aligned.

## 4. Publishing to HubSpot (only on Fabricio's go)

- Templates: `PUT https://api.hubapi.com/cms/v3/source-code/published/content/flieber-2026-b/templates/<page>.html` with `-F file=@hubspot/build/<page>.html`. Live immediately.
- Before uploading, download the live template and diff it against the build with the CSS stripped: content differences must be only the intended ones.
- Agent files in File Manager (folder /flieber-2026): llms.txt 223391226952, llms-full.txt 225564627304, capabilities.json 223386495509. `PUT /files/v3/files/{id}` with options `{"access":"PUBLIC_INDEXABLE","overwrite":true}`.
- Page settings (title, meta description, head HTML) override templates: `PATCH /cms/v3/pages/site-pages/{id}/draft` then `POST .../draft/push-live`. Check for pending drafts first.
- Redirects: `POST /cms/v3/url-redirects` (format of existing ones: routePrefix `http://www.flieber.com/<path>`, isMatchFullUrl true, isOnlyAfterNotFound false, 301).
- HubSpot's cache takes about 1.5 to 2 minutes; verify on www.flieber.com after that.
- The live homepage template is not the prototype in `index.html`: patch it by hand, never upload the prototype.

## 5. Rules that hold for every page

From Fabricio, across this project (on top of the brief):

- Never edit, delete or publish anything in HubSpot without Fabricio's explicit go. Reading is fine.
- Railway preview first, HubSpot after approval. No pull request unless asked.
- Keep the history of every version (home variants, snapshots, brief snapshots, decision log).
- Copy: no em dashes, sentence case, no final period on headings, no serial comma, no fluff. Never invent numbers, customers, URLs, integrations, product capabilities or security claims. Never mention the founders' other companies. Never "run it for you", "take over" or "owns" planning.
- Questions to Fabricio go in a two-column table: question | suggested answer.
- Critical pushback, no glazing, concise answers.

From the brief (see the doc for the full text): one offer, no "Managed Services", no plan names (Lite, Core, Full), no Self-Serve and no software-only option; "specialists who work with your team", never "alongside" or "run by Flieber"; "your team keeps every call"; the 2020 test (no dashboards, reports, visibility, single source of truth); native integrations only Amazon, Shopify, Walmart, NetSuite, Flexport, Google Sheets; MIT study only as cited outside proof; card row layout rules.

Decided by Fabricio after the brief, and already in V16 (the brief may lag behind these):

- Proof: 1,000+ brands since 2019 (not "100+ today", which reads as churn); the four results for brands using Flieber 12+ months (38% more sales, 62% fewer stockouts, 17% less excess inventory, 88% less time on replenishment decisions), always with "averages, not a guarantee"; customer logos and quotes as on the live site; the team (former operators, senior AI team, process consultants, at the intersection of planning, operations and technology). Native integrations are not proof.
- The specialists' value: they work with the team to make every planning cycle more streamlined and complete (best practices, a second set of eyes, better data or automation built into the platform); involvement ranges from reviewing plans to preparing the whole planning cycle for the team's approval. Not "move routine work onto automations".
- No setup-time claim ("within the first month, you already start seeing measurable value").
- Product views come from the approved videos' scenes, labeled "Illustration · Flieber Demo Account · fictional products and people". yourbrand.flieber.com is not live; illustration only.
